\chapter{Implementation and Interfaces}

\section{React Terminal and Flask API}
The final application serves a React, TypeScript, and Tailwind Terminal at
\code{/} from a committed production build. Flask continues to expose the
same read-only JSON API. Client routes return the application shell on a
browser refresh, and the build can run without Node installed. The earlier
seven-page template and static dashboard was an intermediate version; its
dedicated files were removed from the final branch.

Seven views divide the review workflow: Overview, Anomaly Feed, Stock Detail,
News, Watchlist, Pipeline, and Evaluation. Overview combines stored coverage,
activity and flag summaries with the Market Map. The other views provide
filtered flags, stock history, source-linked news, a refined queue, output
status, and method comparison.

\section{Market Map and signal inspector}
The Market Map contains 83 company-share tiles. The 85-series analytical file
also holds PX1 (TUNINDEX) and TBIDX (Tunisian Bond Index), which are not
company tiles. Tile area is weighted by average traded value over the latest
20 stored sessions, not market capitalization. A company with no trade on
the aggregate as-of date is grey; an amber outline identifies recent flags.
A mobile layout presents the symbols as a list.

Selecting a tile or flag opens the signal inspector, which shows stored
market and flag context and available news without assigning a cause.
Navigation, tiles, and inspector controls support keyboard use. Motion is
reduced when the operating-system preference requests it.

\section{Pipeline, evaluation, and caching}
Pipeline reports local output files and the read-only evaluation manifest.
Evaluation displays sourced-event coverage, Wilson intervals, method
comparison, workload, and controls. The reference cannot be retuned in the
interface.
\TerminalShot{../assets/screenshots/pipeline.jpg}{fig:pipeline}
{Pipeline: source coverage and integrity checks.}
\TerminalShot{../assets/screenshots/evaluation.jpg}{fig:evaluation}
{Evaluation: method hits, workloads, and control flags.}

The CSV loader caches by resolved path, modification time, and read options,
and returns copies. A changed file receives a new cache key. The news cache
uses the combined news file's modification time for parsed records and
indexes. These mechanisms are tested for response equality and file-change
reload. Earlier endpoint timing figures were removed because they were not
remeasured on the final application.
