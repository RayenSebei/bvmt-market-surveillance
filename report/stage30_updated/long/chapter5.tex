\chapter{Implementation and Interfaces}

\section{React Terminal and Flask API}
The final application serves a React, TypeScript, and Tailwind Terminal at
\code{/} from a committed production build. Flask continues to expose the
same read-only JSON API. Client routes return the application shell on a
browser refresh, and the build can be run without Node installed. The
earlier seven-page template and static dashboard was an intermediate version;
its dedicated files were removed from the final branch.

Seven views divide the review workflow: Overview, Anomaly Feed, Stock Detail,
News, Watchlist, Pipeline, and Evaluation. The Overview combines stored
coverage, activity and flag summaries with the Market Map. The Anomaly Feed
supports filtering and selected-row review; Stock Detail shows one
instrument's stored history; News preserves source links; Watchlist presents
the refined queue; Pipeline reports available outputs; and Evaluation
shows the frozen detector and Phase 2 comparisons.

\section{Market Map and signal inspector}
The Market Map contains 83 company-share tiles. The 85-series analytical file
also holds PX1 (TUNINDEX) and TBIDX (Tunisian Bond Index), which are not
company tiles. A tile's area is weighted by average traded value over the
latest 20 stored sessions; it is not market capitalization. A company with no
trade on the aggregate as-of date is grey, and an amber outline identifies
recent flags. A mobile layout presents the same symbols as a list.

Selecting a tile or flag opens the signal inspector. It exposes the selected
symbol's stored market and flag context, preserving links to available news
rather than assigning a cause. Navigation, tiles, and inspector controls
support keyboard use. Motion is reduced when the operating-system preference
requests it.

watchlist. Stock Detail shows observations and markers for a selected
instrument. The News view draws from the stored ilboursa collection;
a local match is context, not a verified explanation. The Watchlist shows
ten spike rows and six decay rows in the refined queue.

\section{Pipeline, evaluation, and caching}
Pipeline reports the status of local output files and the read-only
evaluation manifest. Evaluation displays sourced-event coverage, Wilson
intervals, method comparison, workload, and controls. The reference
detector cannot be retuned from the interface.

The CSV loader caches by resolved path, modification time, and read options,
and returns copies. A changed file receives a new cache key. The news cache
uses the combined news file's modification time for parsed records and
indexes. These mechanisms are tested for response equality and file-change
reload. Earlier endpoint timing figures have been removed because they were
not remeasured on the final application.
